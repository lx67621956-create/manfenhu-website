# 满分虎 成绩测评工具 实施计划

> 规划文档 — 尚未执行。

**Goal:** 给学员体测后，教练输入 年级/性别/各项目成绩 → 自动生成专业测评报告：单项得分、总分等级、柱状图+雷达多维图、指导性描述（**不提具体训练方法**），可外化成分享给家长的测评卡片/文字报告。

**Architecture:** 移动端单页静态 HTML（`public/tools/assessment.html`）+ 内嵌评分表 JS 数据文件，纯前端计算与图表（手写 SVG，无外部 CDN 依赖），复用现有工具的品牌视觉体系（#FF6B35 暖橙、自定义 CSS、不用 DaisyUI）。

**Tech Stack:** 原生 HTML/CSS/JS，SVG 手绘柱状图 + 雷达图，无构建步骤，Vercel 静态部署。

---

## 1. 工具定位（与现有工具的区别）

| 工具 | 输入 | 输出 |
|---|---|---|
| 课后总结生成器 | 项目×完成度 | 评语+回家建议文案 |
| 家长群内容生成器 | 天气/节气/节日 | 群发文案+海报 |
| **成绩测评工具（新）** | **年级+性别+各项目实测成绩** | **评分等级 + 图表 + 专业描述报告** |

- 这是**数据计算型**工具，不是文案生成型。
- 外化对象是**家长**：报告要显得专业、有说服力，让家长直观看到孩子各项素质在同龄人中的位置。

## 2. 需要用户提供的数据（关键前提）

1. **年级范围**：覆盖哪些年级（如 小学4/5/6年级、初中1-3年级）？
2. **项目清单**：测评哪些项目（如 50米跑、跳绳、仰卧起坐、坐位体前屈、立定跳远、引体向上/斜身引体、800米/1000米跑……）？
3. **评分标准表**：每个 年级×性别×项目 的 成绩→得分 对照（这是核心数据，用户明确会给）。
4. **等级划分**：优秀/良好/及格/不及格的分数线（如 90/80/60）。
5. **总分算法**：各单项平均，还是按权重加权？

## 3. 功能设计

### 3.1 输入区
- 年级下拉（按用户数据范围）
- 性别切换（👦男/👧女）→ 影响项目和评分标准（男1000米/女800米；引体/斜身引体）
- 各项目成绩输入框（带单位提示：秒/个/厘米/米）

### 3.2 评分与等级
- 对照评分表计算每项得分（0-100）
- 单项等级徽章（优秀/良好/及格/不及格）
- 总分 + 综合等级

### 3.3 图表（专业性外化核心）
1. **柱状图**：各单项得分 vs 满分线（直观对比强弱项）
2. **雷达图（多维图）**：身体素质五维模型 —— 速度 / 耐力 / 力量 / 柔韧 / 协调，每个项目映射到维度，展示综合素质画像
3. （可选）**同龄参照带**：单项成绩在 及格线→满分线 区间中的位置

### 3.4 指导性描述（重要约束：不提训练方法）
- **单项点评**：描述该项目当前所处水平（"处于同龄中等水平"），只说表现不说方法
- **综合评语**：整体画像 —— 优势维度/薄弱维度、发展均衡性
- **发展方向提示**：方向性描述（如"耐力素质是目前的主要提升方向"），**严禁出现** 具体动作/组数/次数/训练方法
- 描述库需与课后总结评语规范一致：零处方词，只描述现状

### 3.5 外化输出
- **文字版测评报告**：一键复制，发微信给家长（姓名/署名由用户自己加，沿用惯例）
- **报告卡片图**：品牌化测评卡片（LOGO+标语+等级+图表），可长按保存分享

## 5. 实施步骤

1. **收集数据**：用户提供 年级范围/项目清单/评分标准表/等级线 → 我整理成 `assessment_data.js` 草案
2. **确认数据**：草案给用户核对（数据准确性要求极高，必须逐项确认）
3. **开发页面**：输入区 → 评分逻辑 → SVG 图表 → 描述生成 → 外化输出
4. **本地验证**：Node 脚本/浏览器跑通多组边界数据（满分、及格线、零分、异常输入）
5. **手机实测**：用户真机测试
6. **部署**：推送到 Vercel，验证 `manfenhu.com/tools/assessment.html`

## 6. 验证清单

- [ ] 描述库无训练方法词汇（禁 组/次/动作名/间歇/冲刺等）

## 7. 风险与开放问题

- **评分表体量**：若年级×性别×项目×分数档位较多，数据文件会大，需确认是否接受
- **描述库边界**：什么叫"训练方法"的界定需要用户把关 —— 我会给描述库草案让用户审
- **是否要历史对比**：本期不做学员历史成绩曲线（保持简单，用户偏好越简单越好）
- **分享图实现**：雷达图/柱状图转图片在移动端可用 canvas 截图方案，需在真机验证
